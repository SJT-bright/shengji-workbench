# 声迹 · 录音第二大脑（macOS App）

本仓库提供声迹的 macOS App 源码。应用有独立窗口、Dock 图标、原生文件夹选择器与保存对话框；本仓库不包含用户录音、数据库、模型权重或预构建安装包。

当前版本为 **0.6.0**，新增深浅外观、连续回放与迷你播放器、持久化编辑草稿、回顾档案和大资料库性能改进。完整更新见 [CHANGELOG.md](CHANGELOG.md)。Apple Silicon 的 macOS 安装包从 GitHub Releases 下载，要求 macOS 13.5 或更新版本；模型与转写环境仍需按下文配置。

## 日常使用

1. 将 MP3 / M4A / WAV 录音或 UTF-8 的 TXT / MD / SRT / VTT 转写稿拖到窗口任意位置；也可直接粘贴文字、批量选择文件，或放入 `~/Documents/声迹收件箱`。
2. 声迹运行时每 5 秒检查文件夹，文件稳定后自动导入。同内容不重复添加。
3. 音频在本机先转写，再由本地 Qwen 自动生成标题、分类。内置工作沟通、学习成长、生活记录、灵感随想、会议纪要、项目推进、读书笔记、课程学习、访谈交流、个人复盘和待确认共 11 类。侧栏「管理分类」支持新增、改名、颜色、图标和删除，自定义分类也提供给 AI；手动指定分类会保留。
4. 自动去除明确口水词，生成整理稿、摘要、关键原话、学习点与行动项；整理稿与摘要并排在同一详情页，原文单独保留。点击记录可修改分类、标题和复盘内容，也可更正录音日期。

「自动整理设置」中可以选择录音豆实际导出的文件夹，启停监测、更换模型或打开 Ollama。只监测所选目录的直接文件，不递归扫描。关闭窗口后应用继续运行；菜单退出 App 后暂停，下次启动继续检查。

## 智能整理边界

默认使用本机已安装的 `qwen2.5:7b`，可选 `qwen3:14b`。模型由本机 Ollama 运行，不把转写发送到云端，不需额外购买 API。App 集成了模型调用与队列，并未在安装包中重复附带数 GB 权重。

保留转写原文及原始源文件。关键片段必须逐字存在于原文；摘要与学习点属于 AI 整理，可编辑确认。多段长文完整分块处理再汇总，不静默截断；单次 AI 整理最多 80,000 字符。更长原文仍可保存，界面会提示拆分后重试。整理失败不生成伪结果，原文保留并显示错误。AI 处理期间手动修改不会被后台结果覆盖。

文件夹导入时日期默认来自文件修改时间，并明确标注依据；不会把它冒称为真实录音时间。尚未连接录音豆厂商账号，使用导出文件或本地文件夹接入。

本机中文音频转写依赖本地 FunASR Paraformer 模型、Python 环境及 `ffmpeg`、`ffprobe`，全程离线。默认配置查找 `~/phone-asr-selfhosted/venv`；模型和 Python 环境未打包，换机使用需自行配置相同依赖。每个音频最多 100 MB / 2 小时，文字文件最多 5 MB（解析后原文最多 50 万字符）。不支持的格式会明确提示。转写失败可重试或补充已有文字稿。

## 数据与备份

数据目录：`~/Library/Application Support/Shengji/`

- `library.sqlite`：SQLite 数据库，保存记录、分类、整理状态、设置和去重信息，事务写入。
- `library.json`：升级前的旧库保留副本；新版首次启动会迁入 SQLite，不再向此文件写入。
- `originals/`：原始文本（字幕时间轴和换行一起保留）。
- `audio/`：原始音频，支持详情回放。
- `app.log`：本地服务启动日志。

清理浏览器缓存不会删除 App 数据。完整 JSON 备份包含分类、原始文字、音频、日/周/月/年回顾和行动完成状态；支持恢复旧版 v1/v2 备份。恢复旧备份时，备份中缺少的回顾和行动完成状态置空，避免混入当前资料库的内容；当前机器的模型与收件夹设置保留。旧浏览器版本在同一浏览器打开更新页面、且 App 库为空时会迁移其已有记录，迁移不删除旧浏览器副本。其他情况请先导出旧备份后在 App 恢复，恢复会替换当前库。

## 开发与验证

- 需要 Node.js 22.13 或更新版本（使用内置 SQLite），然后执行 `npm ci` 安装锁定依赖。
- `npm run build` 构建界面。
- `npm run app:build` 构建 `release/声迹.app`，需要 macOS Swift 工具链；运行时 Node 已捆绑。
- `node server.mjs` 启动开发本地服务（5189）；`npm run dev` 启动热更新界面（5178）。不要与已运行的 App 同时占用 5189。
- `npm test`：隔离测试模型契约、音频转写、分类管理、文件夹导入、去重、权限、竞态与备份完整性。
- `npm run build && npx playwright test`：隔离库、真实 Chrome 验证导入、编辑、收藏、持久化、搜索、导出及手机布局。
- 并行开发时可用 `SHENGJI_UI_TEST_PORT=5297 npx playwright test` 指定独立测试端口。
- `node tests/verify-live-model.mjs`：独立临时目录里的合成文本，真实验证文件落盘→自动导入→本地模型→分类整理→去重。需要 Ollama 与 Qwen。报告在 `verification/live-model.json`。

- `node tests/verify-live-audio.mjs`：独立临时库中的合成 MP3，真实验证上传→离线转写→本地模型整理→原音回放与去重。报告在 `verification/live-audio.json`。
- `node tests/verify-live-retrieval.mjs`：独立临时库中的合成长稿，使用本机 Qwen 验证长稿后半部分的问答与逐字引用。报告在 `verification/live-retrieval.json`。

本地服务仅监听 127.0.0.1，校验 Host/Origin 和会话令牌。安装包使用本机临时签名，尚未做面向其他 Mac 分发的公证。

## 0.4 新增工作流

- 纯音频拖入后直接进入「处理队列」，依次转写、去口水词、生成摘要；可以暂停后续任务或重试失败项。
- 「问录音」检索已有原文，再由本地 Qwen 回答并附可回看的逐字引用；只处理候选记录，长记录会明确标记截取范围，不保证穷尽整个库。
- 「应用关联」提供收件箱、数据库信息和本地 API 说明。原生入口包括 Finder「打开方式」、`shengji://record/<id>`、Markdown 导出和系统分享；尚未对接指定第三方 App 的专有 API。
- 去口水词采用保守删除，不改写观点、数字或否定；可能保留不确定的口语词，整理结果仍应对照原文。
- 当前已安装 Qwen 是文本模型：音频识别实际使用本地 FunASR Paraformer，Qwen 负责整理与问答，未安装 Qwen-ASR。

相关验证可运行上文列出的本地测试与构建命令。

## 0.5 使用改进

- 详情页切换记录时保护未保存的编辑；调整干货标签或价值标记时保留正在填写的内容。
- 修复单个音频已导入后，在同一窗口继续粘贴文字无法保存的问题。
- 完整备份同时保存各周期回顾与行动完成状态；无效备份在恢复前拒绝，不替换当前资料库。
- 恢复资料库后，旧库仍在生成的回顾不会写回新库。
- 「问录音」按问题中的词在完整原文内选择上下文片段，可覆盖长稿后半部分，并披露实际读取范围。采用关键词匹配，不是语义向量检索；回答仍须回看引用核对。
- 0.5.1 统一导航图标，扩充分类可选图标；快速查找可用方向键选择、回车打开，界面动效遵循系统「减弱动态效果」。

## 键盘快捷键

- ⌘K 聚焦搜索框并全选；/ 同样聚焦搜索框；Esc 先清空搜索，再移开焦点。
- ⌘P 随时呼出快速查找面板：↑↓ 选择、回车打开，Home/End 跳到第一项或最后一项，Esc 关闭。
- 详情页内：←/→ 切换上一条、下一条记录；空格播放/暂停音频。
- ? 打开快捷键说明表；快速查找面板的「操作」里也有入口。
- 以上按键在输入框、文本域内输入时不触发；←/→ 与空格只在详情弹窗打开时生效。

## 外观主题

- 外观有三种：跟随系统（默认）、浅色、深色。侧栏底部「外观」按钮与顶栏的圆形图标都可切换，点击在三态间循环。
- 「跟随系统」随系统深浅色实时变化；选定的偏好保存在本机，下次启动保持。
- 深色是暗紫玻璃变体，滚动条、文字选区和日期、下拉等原生控件一并转暗；只换颜色，结构与动效不变。

## 录音回放

- 详情页顶部是自定义播放器：播放/暂停、波形律动、进度拖拽定位；右侧按钮在 0.75×–2× 之间循环切换倍速。
- 倍速偏好保存在本机，重启应用后继续使用。
- 切换详情标签、后台刷新或关闭详情页时，播放不从头开始；关闭后由右下角迷你播放器接管，再打开同一记录时接续当前进度。点击「停止播放」结束回放。
- 音频只保存在本机；个别编码无法回放时会有提示，原文件不受影响。

## 回顾档案

侧栏「回顾档案」汇集全部已生成的日提炼、周报、月度回顾与年度回顾，按时间倒序排列；点击展开阅读，可单份导出或整包导出 Markdown。生成入口在首页（提炼今天/本周/本月/今年）与每日足迹（提炼这一天）。此处为只读汇总，不影响原文与整理稿。

## 设备连接（0.5 · 演示与自建网关）

侧栏「设备连接」提供连接来源工作台，当前支持两类来源：

- **演示设备**：内置夹具（「演示录音」），无需任何设备即可走通 配置 → 测试 → 同步 → 去重 → 转写/整理队列 的完整链路。所有演示结果都带「演示设备 / 模拟」标记，不是真实设备录音。
- **远程 manifest 来源**：连接你自建的兼容 HTTPS manifest 网关（v1 JSON：`{version:1,device:{id,name,model},files:[{id,name,url,size,mtime,sha256?}]}`）。仅允许公网 HTTPS，拒绝本机/内网/保留地址与重定向降级；访问令牌只保存在内存，重启后需重新输入。

诚实边界：声迹**不能也不声称已连接讯飞官方云或厂商私有云**。没有真实讯飞录音笔型号与官方接口前的设备适配属于未来 adapter 能力。移除来源配置不会删除已导入的记录与音频；同步失败不删除原件、不产生伪记录。同步导入的记录走既有导入路径（内容哈希去重、日期依据为文件修改时间且可更正），记录来源标记为「设备同步」，`source.path` 形如 `connector:<来源id>`。

来源配置保存在数据目录 `connectors.json`（不含令牌）。相关测试：`tests/connectors.test.mjs`（连接器服务）、`tests/connector-routes.test.mjs`（API 路由）、`tests/device-connections.test.mjs`（UI 模块）；`node tests/verify-devices-ui.mjs`（对运行中的隔离实例做真实 Chrome 点击走查，`SHENGJI_UI_BASE` 可指定地址）。
